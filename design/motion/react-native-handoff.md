# React Native motion handoff

This is DESIGN_ONLY guidance for owner-led implementation. Resolve durations, curves, and spring values through the existing token source. The [motion architecture](../MOTION.md) defines the functional stack and the [Lottie asset policy](../animations/README.md) governs optional decorative assets.

| Area | Expected implementation behavior |
| --- | --- |
| Press feedback | Use Reanimated for the visual response to the platform press state. Activate on release inside the unchanged target. Release outside cancels. The separate FigCraft release frame demonstrates the visual handoff. |
| Picker sheet | Use Gorhom Bottom Sheet. Keep one Edit Task draft behind the overlay. Apply the approved 28% Ink backdrop and preserve the fixed 80 px header and 100 px confirmation region when the sheet body scrolls. Confirm commits the selection, Close restores focus, and device Back dismisses the overlay before navigating away. Verify safe areas, drag-to-dismiss and snap points on devices. |
| Task completion | Update completion in the current view and announce the outcome. Use Reanimated for the visual state change. Preserve the approved Planner layout, task identity and nested list offset through completion and Undo. At compact height the task and Undo are reached through the original content scroll. The FigCraft pilot switches variants in the existing viewport. |
| Couple celebration | Keep connection confirmation immediate and preserve the position and full approved size of Open Us. A separately approved decorative effect may play once per successful connection. The mascot transforms in the FigCraft pilot are design evidence. Open Us starts the demo and the Back arrow replays it after the settle through review bindings. |
| Route transition | Use React Navigation for screen entry, exit, tabs, and history. Restore the caller’s focus or scroll position where specified. |

Respect the platform’s reduced-motion preference. Verify gestures, touch cancellation, focus restoration, safe areas, and transition behavior on iOS and Android. Log real-device findings using the [device checklist](../handoff/device-test-checklist.md).

## Reusable component contracts

- **Motion preference** reads the platform setting, subscribes to changes, and stops active decorative playback if reduced motion is enabled. Use `AccessibilityInfo` for the live setting. [React Native accessibility events](https://reactnative.dev/docs/accessibilityinfo#supported-events)
- **Loading cue** shares one active clock across the three dots. Pair the loop with a visible status and stop on blur, unmount, or request resolution.
- **Success accent** takes an event identity and a visual variant. It animates the existing illustration or icon without delaying the status or Undo. Cancel on a new event or when the success state is reversed.
- **Particle burst** shares a single progress value across a capped pool of simple views. Compute positions and colors once per event. Animate transforms and opacity on the UI thread. Keep the overlay outside accessibility traversal and touch handling. Avoid per-frame React updates, layout reflow, and continuous spawning. Profile on a representative lower-performance Android device before increasing the count.
- **Artwork motion** takes the approved image, its display bounds, and one mode for loading or a single float. Keep the visual layer within the original clip and preserve a still result. Use the existing Expo Image path for compatible SVG.

## Proposed runtime rollout after DESIGN_ONLY

1. Obtain explicit owner approval for the pilot and for any move beyond DESIGN_ONLY. After authorization, the owner checks the installed development client against the lockfile before testing.
2. Start with Home ↔ Tiny Planner, Edit Task picker entry and dismissal, and the Planner checkbox with Undo. Exercise the modal stack, cancellation, focus, scroll offsets, and reduced motion. Use platform route transitions where Native Stack cannot apply the proposed nominal duration.
3. Test App Loading and Save Success next. Add the bounded celebration at one milestone and the Kitchen and Empty State artwork cues once the shared lifecycle works. Keep each increment optional so static behavior can be restored independently.
4. Before expanding, review compact, standard, and tall sizes on iOS and Android. Test repeated events, background and foreground, mid-effect Reduce Motion changes, safe areas, and gesture interruption. Compare resting screenshots with approved geometry and inspect actual device motion. Submit results for manual visual approval.

The [usage map](../animations/usage-map.md) contains the timing storyboards and FigCraft limits. The [asset manifest](../animations/asset-manifest.json) records the five blocked, unacquired LottieFiles selections. Optional Lottie would require legal and visual verification as well as a separate platform test before use.
